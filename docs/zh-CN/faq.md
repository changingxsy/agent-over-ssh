# 常见问题

[English](../faq.md) · 简体中文 · [文档目录](../../README.zh-CN.md#文档)

### 和 VS Code Remote-SSH 有什么区别？

Remote-SSH 会把编辑器后端和工作区扩展放到服务器上运行，所以服务器上的 AI 扩展需要在每台机器上各自安装、登录，并且能访问网络。agent-over-ssh 把 Agent 完全留在本机，只给它两条通往服务器的窄通道：同步的文件和 `rdev`。你在本地照样可以用任何编辑器，这些文件就是普通的本地文件。

### 为什么不直接在服务器上装 Claude Code 或 Codex？

可以装，但那样每台服务器都需要 Agent 本身、登录状态、API key、Git 凭据、MCP 和技能，还要能访问外网来调用模型 API。服务器经常更换，有的连不上外网，共享服务器还会把你的凭据放在别人能接触到的地方。用这个项目，Agent 只需要在本机配置一次；新增一台服务器只要一个 SSH 别名加一次 `remote-dev-init`。

### 为什么不用 sshfs 或 rsync？

- **sshfs** 每次访问文件都要走一次网络往返；Agent 会大量读取和搜索文件，速度会很慢，而且网络一断挂载也断了。另外你仍然需要一种运行命令的方式。
- **rsync** 是单向、手动的：不会告诉你服务器上的副本什么时候过期，也检测不到冲突的修改。mutagen 持续双向同步，`rdev` 也会在同步刷新完成、没有冲突之后才运行。

### 服务器需要能上网或开放端口吗？

不需要，只要 SSH。mutagen 和 herdr 的辅助程序都是从本机通过 SSH 部署到服务器上的，通信也走 SSH 会话本身。当然，你项目自己的命令可能需要联网（例如 `pip install`）。

### 能在容器里用吗？

可以，只要你能 SSH 进容器（或进入项目目录所在的主机）。除了 SSH 不需要任何其他端口。

### 断网或合上笔记本会怎样？

正在运行的命令会继续在服务器上运行。本地修改会排队，重连后同步。之后 `rdev up` 会列出没收取的任务，用 `rdev --wait TOKEN` 收取即可。见[命令分流 → 断网](command-routing.md#断网与合上笔记本)。

### 能看到命令正在做什么吗？

可以。命令运行在真实的终端 pane 里：打开服务器的 herdr 会话（例如 `herdr --remote devbox`），切换到 `rdev-<name>` 工作区即可。在本机也可以用 `rdev --log TOKEN` 打印日志。

### 能同时用多台服务器吗？

可以。每个项目对应一台服务器上的一个目录；不同项目可以用不同服务器，一台服务器也可以承载多个项目（各自有独立的 `rdev-<name>` 工作区）。单个项目不能同时指向两台服务器，需要的话再建一个项目。

### 能同时运行多个命令吗？

每个项目一次一个：pane 忙时会拒绝新命令，这样输出和退出码不会混淆。长任务用 `--bg` 启动；需要并行时，在命令内部拆分（例如用一个脚本启动多个进程）。

### 只支持 Claude Code 和 Codex 吗？

`rdev` 和 `remote-dev-init` 都是普通的命令行工具，任何能运行 shell 命令的 Agent，或者你自己，都可以使用。技能和 hooks 是为 Claude Code 和 Codex 编写的。

### 支持哪些平台？

本机端在 macOS 上测试过，Linux 应该可用（未测试）。不支持原生 Windows。服务器需要 SSH 和 `bash`。

### 服务器上最终会有什么？

同步过去的项目代码、只留在服务器的数据、一个 herdr 工作区、`~/.rdev/run/<name>/` 下的运行日志，以及 mutagen / herdr 的辅助程序。没有 `.git`，没有密钥，也没有 token。
